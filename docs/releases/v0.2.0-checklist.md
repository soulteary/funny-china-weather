## Before publishing

- [ ] Merge the release-preparation PR and verify the exact resulting main
  commit's CI. The release must contain the finalized documentation as well as
  the code changes.
- [ ] Recheck that `v0.2.0` does not exist on the remote and that the intended
  tag target is the verified main commit. Never move an existing version tag.
- [ ] Create and push an annotated `v0.2.0` tag at that exact commit.
- [ ] Publish the GitHub release using the prepared release notes.

## After publishing

- [ ] In a fresh module, download v0.2.0 through the Go module proxy and inspect
  the actual module ZIP for `LICENSE`, `icons/README.md` and the 33 SVG assets.
- [ ] Confirm both explicit `@v0.2.0` and `@latest` resolve to the intended
  version, then compile and run an offline consumer of legacy and new APIs.
- [ ] Confirm documentation for `GetObservation`, `GetSVGCodeByName`,

See [the publishing procedure](../releasing.md) for verification commands.
The version tag and proxy-install checks cannot be marked complete before the
tag actually exists. A green offline CI run does not verify live provider
availability; the provider smoke tests remain opt-in.
