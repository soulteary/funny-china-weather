# 性能优化与验证

验证日期：2026-10-26。环境：Apple M5、darwin/arm64、Go 1.27.3。
以下数字来自本机离线基准，不代表线上请求耗时。

## 第一阶段：缓存并发

Flare 示例按地点合并刷新，网络请求与 SVG 渲染在全局锁外执行。
同一地点的等待者直接取得共享刷新结果，即使结果随后被容量淘汰，也不会因为重新查表而重复刷新。
等待支持调用方取消；刷新由发起请求的 context 控制，失败仍按一分钟重试。
不同地点可独立刷新，已有缓存读取不会等待其他地点的网络请求。

新增验证覆盖跨地点隔离、同地点并发合并，以及等待刷新时取消。
原有十分钟刷新、一分钟失败重试、保留旧数据和 SVG 实例隔离测试继续通过。

## 第二阶段：SVG 模板

按内嵌图标和动画/静态模式惰性编译不可变片段，初始化通过 `sync.OnceValues`
合并。请求仅拼接实例前缀，不再重复 XML 解析。缓存只包含 49 个已知资源，
任意用户前缀和未知图标不会增加缓存条目。

优化前基准（300ms）与优化后基准（500ms）的代表性结果：

- clear-day：280,622 → 1,857 ns/op；385,994 → 20,535 B/op；1,392 → 3 allocs/op。
- cloudy-day：125,685 → 978.4 ns/op；133,429 → 8,248 B/op；1,446 → 3 allocs/op。
- rain-heavy：72,784 → 499.3 ns/op；73,631 → 4,935 B/op；842 → 3 allocs/op。
- unknown：9,233 → 89.07 ns/op；10,927 → 488 B/op；240 → 3 allocs/op。

以上为模板预热后的调用：耗时约降低 99.0%–99.3%，累计内存分配降低约
93.3%–95.5%，超过预定的 50% 目标。首次使用仍需要解析；单独的
`BenchmarkIconTemplateCold` 测量 clear-day 原始组合过程约为 273 微秒，
不包含模板切片、惰性初始化和公共 API 的全部首次调用开销。

代价是保留编译结果。全部动画版和静态版初始化后，共 2,884 个片段，
模板和源字符串的保留内容约 953,804 字节（约 0.91 MiB），另有切片、映射、
闭包和分配器开销；未使用的图标不会触发模板解析。

49 个资源的两种模式、三种前缀均与原始组合函数逐字比较，包括与内部标记
相同的调用方前缀。原有 XML、CSS、动画、静态降水和实例隔离测试全部通过。

## 第三阶段：地点复用与缓存边界

新增 Flare `Cache.GetAt(ctx, selectedLocation)`，直接调用
`weather.GetObservationAt`，固定地点刷新只有一次天气请求。
原有 `Get` 继续支持关键词和序列化地址；两种入口使用独立缓存空间。

缓存最多 128 条，包含正在刷新条目。每次访问惰性移除闲置一小时的条目，
容量满时淘汰最久未访问且不在刷新的条目。所有条目均在刷新时，新地点等待
刷新完成或 context 取消，不突破容量上限。没有后台任务。
淘汰会同时丢弃该地点的旧天气与重试时间。

新增测试验证容量边界、最近使用顺序、闲置淘汰、刷新期间固定条目、
容量等待取消与恢复，以及直查刷新每次只发送一个天气请求。
请求计数测试使用本地拦截响应，没有访问实时服务。
